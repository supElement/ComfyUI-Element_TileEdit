# ComfyUI-Element_TileUpscale

A tile-based refinement/editing/enlargement node designed for image editing models. It allows models like Qwen-Image 2.1 / Edit 2509 / 2511, FLUX.3/FLUX.2 klein, Krea2 to maintain cross-tile consistency during enlargement with a three-layer mechanism: tile reference ≫ frequency separation fusion > neighbor context. The denoise redraw strength can be safely set to 0.7–1.0 while preserving the identity, structure, and texture of the original image; the reference strength per sampling step can be customized to control the balance between repair strength and consistency; it extends the capabilities of some image editing models (limited to single image). This is something traditional img2img tile enlargement cannot achieve.

- Krea2 requires [krea2_identity_edit](https://huggingface.co/conradlocke/krea2-identity-edit/tree/main) lora.

## Node Overview

| Node | Function |
|---|---|
| **Element Tiled Upscale** | Integrated node: Enlarge → Split → Per-tile reference redraw → Frequency separation fusion, one-click output |
| **Element Tile Split** | Only does enlargement + split + per-tile encoding, outputs per-tile LATENT / CONDITIONING / original tile, samplingAssign to ComfyUI native KSampler |
| **Element Tile Merge** | Merges the list of images after per-tile decoding using the same low-frequency/high-frequency separation + feathering weights, optional per-tile color matching |
| **Element Krea2 In-Context Patch** | Model patch: Allows Krea2 to consume the reference latent attached to conditioning in an identity-edit in-context layout |
| **Element Strength Schedule** | Model patch: Attaches a gradual reference_strength schedule to the model, for use in ElementTileSplit + native KSampler workflow, KSampler's model input must connect to the output of this node. The integrated node includes the same schedule and ignores upstream attachments, while the single-node workflow directly uses its built-in parameters. The i-th value affects the i-th sampling step (starting from 0); if fewer than steps, repeat the last value; if more, truncate; single value = constant. 1.0 = full reference; 0 = no reference for this step; pure 0/1 list uses single multiplicative power, non-integer values for steps ≠1 use double forward. Lower parameter settings lead to more drift, to ensure consistency, the first few steps should have high values, it is recommended to set the first few steps to 1 and gradually reduce the values for the later steps based on the model used, which is more beneficial for repairing flaws. This setting is ineffective for non-image editing models, such as sdxl, Qwen image 2512, etc. |

## Why It's Needed

Almost all traditional tile-based enlargement nodes (TTP, Ultimate SD Upscale and its derivatives) follow the **img2img path**: adding noise to the low-resolution original image and feeding it to the model to denoise and reconstruct.
This path has a **structural flaw**—"redraw strength" and "feature retention" share the same channel, which is the denoising value: low (≤0.4), more original image signal is retained, features approximately match, but the model's redraw freedom is insufficient → **blur, plastic feel, missing details**; high (≥0.5), details and sharpness improve, but the original image signal is drowned out by noise → **identity shift, structural change, cross-tile ghosting**
Under the img2img paradigm, this contradiction **cannot be resolved** because you only have one information channel. Therefore, the denoising value of traditional nodes is effectively locked in the narrow window of 0.1–0.5, and the upper limit of enlargement is also stuck there.

Element_TileUpscale splits "redraw" and "feature retention" into two independent channels, injects the original image as an independent reference signal into the model, and the reference signal does not participate in adding noise or decay with the denoising value. The denoising value **only controls redraw strength, no longer controls feature retention**

- **Denoise 0.7-1.0**: The target can almost be reconstructed from pure noise (there are differences between models), with details completely generated by the model; at the same time, the model sees the reference image every step, knowing what content, identity, and texture to generate. **Clarity and consistency are achieved simultaneously.**
- **Tile Reference**: Prevents each tile from acting independently; provides precise local correspondences for each tile to prevent detail misalignment. Allows **cross-tile consistency** even under high denoising.
- **Low-frequency / High-frequency Separation Fusion**: During stitching, low-frequency (exposure, color) follows smooth weights, while high-frequency (details, texture) almost dominates the weights, avoiding contour ghosting and seam blurring.
- **Neighbor Context**: Already generated adjacent tiles are fed back as input context to the next tile with full intensity, making the model treat them as "content to be continued," rather than relying on overlapping areas to obscure seams. (For reference-anchor models, neighbor context mainly softens the micro-texture of the seam band when denoise < 1; structural and identity consistency is handled by the shared original image reference, which is why redo_first_tile is almost ineffective for editing models.)

## Known Limitations and Disadvantages

### 1. Relies on specific model capabilities, not friendly to non-image editing models

- The entire value of the node is built on the **model's ability to reference latent space**. Using models like SDXL, ordinary Flux t2i, Qwen-Image-2512 without reference capabilities will degrade it into a normal tiled img2img—**at this point, it is no better than tools like TTP**.

### 2. Model identification depends on reverse engineering, may have cross-version stability issues in comfyUI

- Model identification relies on **substring matching of class names** (`"flux" in type(dm).__name__.lower()`), **tokenizer signature reflection** (`inspect.signature`), and `vars()` traversal. None of these are stable APIs.
- Krea2's in-context path involves **manual reconstruction of forward propagation**, directly calling `dm.blocks`, `dm.pe_embedder`, `img_slice`, etc. internal structures; the Patch node also relies on core's `extra_conds` object-patch and DIFFUSION_MODEL wrapper mechanisms. Once the upstream model implementation changes (renaming, signature changes, internal layout changes), the node may **silently fail or crash directly**.

### 3. Higher performance and memory overhead (within acceptable limits)

- Each tile needs to **independently encode the reference latent**; when grounding is enabled, each tile also needs to **re-run the text encoder's vision encoding**. The overhead increases linearly with the number of tiles.
- Krea2's in-context path requires running the full DiT forward, with the token sequence being `text + source + target` three segments concatenated, attention cost is higher than the original.
- As the number of tokens for a tile increases, the attention cost grows **quadratically**, so automatic tile size is limited to 1024–1536. The training resolution limit for identity-edit LoRA is about 2MP, and tiles should not exceed 2MP (1536²≈2.36MP is already over the limit, 1408²≈1.98MP is close to the limit).

### 4. Does not guarantee correctness for unadapted models

## Recommended Denoising Values and Combinations

- Text encoding nodes can uniformly use CLIP Text Encode (Prompt). If a dedicated text encoding node for image editing models is used, do not connect reference images to the text encoding node.
- CFG values should be set according to the model being used.
- For editing models, the denoise value range is 0.6–1.0; for non-editing models, the denoise value should not exceed 0.5.
- For editing models, connect `clip` and fill in `prompt` to re-encode each tile with itself as the vision input; for Krea2 identity-edit, open `reference_mode`.
- If the results are not ideal, prioritize adjusting `grounding_px`, `feather`, and `overlap` rather than lowering `denoise`.

| Model                | Recommended Denoising Value | Reference Injection Method | Consistency | Description                                                                 |
|----------------------|------------------------------|-----------------------------|-------------|-----------------------------------------------------------------------------|
| **Qwen-Image 2.1**   | **1.0**                      | Reference latent precisely inserted at vision token positions (image_slots), tile remains original size without resize | ★★★★★      | Reference signal is most native, and it can often be pushed to the maximum. Details are fully generated by the model, while identity and structure remain consistent |
| **Qwen-Image Edit 2511** | **1.0**                      | 384×384 vision bucket + reference latent dual channel | ★★★★       | Same as 2509, recommend using 1.0 directly, lacks details                  |
| **Qwen-Image Edit 2509** | **1.0**                      | 384×384 vision bucket + reference latent dual channel | ★★★★       | Same source as 2511, reference channel is mature and can be pushed to the maximum, lacks details |
| **FLUX.2 klein base** | **0.7 – 1.0**                | Only reference-latent channel (text encoder is pure text, no vision grounding) | ★★★★       | Lacks vision channel, some facial artifacts, color bias, can use [Smart merge images node](https://github.com/supElement/ComfyUI_Element_easy) for color or deformation correction, can be improved to ★★★★★ when paired with anti-shift LoRA |
| **Krea2 + krea2_identity_edit** | **0.7 – 0.8**                | Manually reconstruct `[text｜source(frame=1)｜target(frame=0)]` in-context forward | ★★★☆       | Best color consistency under high denoising, but sometimes may have artifacts. 0.7–0.8 is the best balance between clarity and stability |
| **FLUX.3 klein turbo** | **0.7 – 0.8**                | text encoder is only text effective, no vision grounding | ★★★        | Lacks details, prone to deformation (may also be due to comfyUI implementation issues), advantage is not prone to artifacts |
| **FLUX.2 klein turbo** | **0.7 – 0.8**                | Only reference-latent channel (text encoder is pure text, no vision grounding) | ★★★        | Lacks vision channel, reference signal is one level weaker, easily prone to artifacts and color bias, can use [Smart merge images node](https://github.com/supElement/ComfyUI_Element_easy) for color or deformation correction, can be improved to ★★★☆ when paired with anti-shift LoRA |
| **Qwen-Image-2512/SDXL series** | **0.2 – 0.5**                | None                         | ★          | Non-editing models lack consistency anchoring, even with methods like ipadapter, the effect is still limited |

- Model combination strategy: It is recommended to use non-distilled models like base or raw, paired with turbo LoRA (weight about 0.8, adjust according to specific models). This balances the high-quality detail restoration of the base model with the generation speed of the distilled model, and effectively avoids high-frequency artifacts (artifacts) that are easily amplified when using pure turbo models directly.
- Reference strength curve (reference_strength): It is recommended to use an "early high, late low" tail relaxation curve. For example, when the total steps are 4, you can fill in 1.0, 1.0, 0.9, 0.8. Since turbo models have very few steps, the strength of each step greatly affects the result. It is recommended that the reference strength throughout should not be below 0.7 (otherwise it is prone to image drift); if feature drift occurs in actual use, the curve can be directly flattened to all 1.0.
- Krea2 model tuning: It is recommended to leave the negative_prompt completely empty. This is because krea2's identity-edit uses an unconditional distribution of "the same image + empty text" during training, leaving it empty aligns perfectly with the training distribution; and when cfg=1.0, the node can also save the encoding time of negative prompt words.

The above tests are limited in number and have biases and subjective factors, so parameters still need to be adjusted according to different situations. Of course, you can also improve the results by using enhanced LoRA or fine-tuned models, but this is not within the scope of the tests.

## Global Prompt (Important)

This node will use the same prompt for every text encoding of the tiles, and each tile only contains a small area of the entire image. What is in the area is determined by the reference image (pixel features); the prompt only tells the model "how to process" this content. Therefore, tips should only contain core principles that apply to all tiles:

### ✅ Should Write

**1. Operation Instructions** — Tell the model what to do during this sampling (applies to each tile):
- `sharpen and refine details, preserve identity and structure, clean upscale`

**2. Global Style / Lighting / Tone** — The atmosphere shared by the entire image (also applies to each tile):
- `cool blue ambient lighting, warm orange rim light, cinematic tone, photorealistic`

### ❌ Should Not Write

**Specific object, character, scene nouns** (e.g., `woman at a computer, glasses, monitor, coffee cup`)，Unless you can be sure that each chunk contains the specific object element in the prompt word:

### Recommended Template

- `sharpen and refine, preserve identity and structure, {global tone/lighting/style}, {image quality word}`

## Parameter Description

### Element Tiled Upscale (Integrated Node)

#### Basic

| Parameter | Description |
|---|---|
| **model / vae / image / clip** | The four basic components. clip is mandatory: it encodes per-tile conditioning, positive/negative input ports have been removed |
| **upscale_by** | Magnification factor, 1.0 = only resampling refinement without magnification |
| **tile_mode** | Tiling method: enabled for "by count," disabled for "by size." |
| **columns** | Visible only when `tile_mode` is set to "by count." Specifies the number of divisions along the width. |
| **rows** | Visible only when `tile_mode` is set to "by count." Specifies the number of divisions along the height. |
| **tile_size** | Visible only when `tile_mode` is set to "by size." Defines the resampling resolution for each tile. 0 = automatic (approximately 4 tiles along the longer side, ranging from 1024–1536 pixels). Larger tiles result in fewer total tiles but increase the processing time per tile. For "identity-edit" LoRA, please ensure each tile is ≤ 2MP. |
| **overlap** | Overlap amount between adjacent slices. 0 = automatic: 15% of slice size, capped at 256px (the smaller of the two). Any non-zero value will be used as-is, without a cap. Higher values result in smoother seams but increase computational overhead (overhead grows quadratically with overlap) |
| **feather** | Feathering strength for inter-tile blending, 1.0 = maximum smoothness, generally unchanged |
| **steps / cfg / sampler / scheduler / denoise / seed** | Same as KSampler, directly use the official recommended values for this model |
| **prompt** | Required. Per-tile re-encoding along with the pixel of this tile (vision input) is the sole positive conditioning source, leaving it empty will cause an error |
| **negative_prompt** | Empty = encode an empty string as the baseline negative condition. Krea2 identity-edit suggests keeping it empty |

#### Optional (Reference Mode Group)

| Parameter | Description |
|---|---|
| **reference_mode** | On = Krea2 identity-edit dedicated in-context path (internal reference passing mechanism within the node, no need to connect Patch node; if connected, it will be automatically removed by this node). Off = General conditioning path (in Krea2, must be paired with a Patch node, which will function normally and properly combine with step-by-step reference strength scheduling) |
| **redo_first_tile** | After all other image tile processing is completed, re-generate the first image tile again so it can use the completed adjacent tiles as context references. This operation is only applicable when multiple image tiles exist. It has a negligible impact on image editing models |
| **grounding_px** | Vision input size for per-tile text encoding, default 768, meaning varies by model: Edit 2509/2511 uses area bucket, 0 or ≥384 always uses official 384×384; Qwen 2.1 ignores this parameter (locks to the block's own size); Krea2 is the maximum visual input side length, 0 = block's own size |
| **reference_strength** | Per-step reference strength (STRING). Directly fill with a numerical list: 1.0, 0.8, 0.5 (comma/semicolon/colon can be used in both Chinese and English), or can accept the strength_string output of [Element_listGraph_Curve](https://github.com/supElement/ComfyUI_Element_easy). The i-th value affects the i-th sampling step (starting from 0); if fewer than steps, repeat the last value; if more, truncate; single value = constant. 1.0 = full reference; 0 = no reference for this step; pure 0/1 list uses single forward calculation power, while values ≠1 with decimals use double forward for those steps. Lower parameter settings are more prone to drift; to ensure consistency, the first few steps should have higher values, it is recommended to set the first few steps to 1 and gradually decrease the values for the later steps based on the model used, which is more beneficial for flaw repair. denoise does not affect this parameter; vision/grounding references are unaffected by this parameter. Invalid for non-image editing models, such as sdxl, Qwen image 2512, etc. |

#### Output

| Port | Content |
|---|---|
| **image** | The final merged full image (main output) |
| **split_images** | List of source images after splitting (for debugging) |
| **resampler_images** | List of generation results per tile (for debugging, allows checking quality per tile) |
| **grid** | Tile grid description for reuse by downstream nodes like Element Tile Merge |

### Element Tile Split

Only performs magnification + tiling + per-tile encoding, sampling is handled by ComfyUI's native KSampler, suitable for scenarios requiring custom sampling details or inserting intermediate processing.

| Parameter | Description |
|---|---|
| **model / image / vae / clip** | clip is mandatory, positive/negative input ports have been removed, per-tile conditioning is encoded by clip + prompt / negative_prompt |
| **upscale_by** | Same as above |
| **tile_mode** | Tiling method: enabled for "by count," disabled for "by size." |
| **columns** | Visible only when `tile_mode` is set to "by count." Specifies the number of divisions along the width. |
| **rows** | Visible only when `tile_mode` is set to "by count." Specifies the number of divisions along the height. |
| **tile_size** | Visible only when `tile_mode` is set to "by size." Defines the resampling resolution for each tile. 0 = automatic (approximately 4 tiles along the longer side, ranging from 1024–1536 pixels). Larger tiles result in fewer total tiles but increase the processing time per tile. For "identity-edit" LoRA, please ensure each tile is ≤ 2MP. |
| **reference_mode** | On = Krea 2 identity-edit: per-tile output vision slot grounding + reference latent dual-channel conditioning, reference is attached to both positive and negative sides; **must be paired with a Patch node** (Split does not reconstruct forward). Off = General conditioning path |
| **grounding_px / prompt / negative_prompt** | Same meaning as the integrated node. Split does not have a reference_strength parameter: step-by-step strength scheduling should use the **Element Strength Schedule** node attached to the model (its output connects to the model input of KSampler) |

**Output**: `tile_positives` / `tile_negatives` (per-tile CONDITIONING list), `tile_latents` (per-tile LATENT list), `grid` (tile grid), `tile_sources` (original image tile list for color matching reference for Merge).

### Element Tile Merge

Reassembles the list of image tiles **after decoding** back into a full image. The blending logic is identical to the integrated node: low-frequency uses smooth feathering weight, high-frequency uses nearly exclusive weight.

| Parameter | Description |
|---|---|
| **tile_images** | Decoded list of per-tile images |
| **grid** | Split output tile grid |
| **feather** | Feathering strength for inter-tile blending |
| **tile_sources** | Optional. Split output original image tiles for color matching reference |
| **color_match_strength** | 0 = disabled. >0: Each resampled tile is color-migrated per channel mean/std against the corresponding original tile (aligns hue, preserves details), requires connection to tile_sources |

**Output**: Merged full image.

Another node from an extension, [Smart merge images node](https://github.com/supElement/ComfyUI_Element_easy), can be used as a replacement, as Smart merge images provides better results for color and distortion correction. 
Smart merge images support partial image splicing, and you can use the workflow below to repair partial images.

## Common Issues

**How to use it? **
Related workflows are provided in the workflow folder.

**Insufficient VRAM?**
Reduce `tile_size` (more tiles, smaller each). Edit 2509/2511 can further reduce `grounding_px`; Qwen 2.1's `grounding_px` is not involved in the calculation, only `tile_size` can be reduced.

**Can SDXL and other standard models be used?**
Yes. The node will automatically degenerate into a standard img2img. Refer to latent being ignored by the model, use `denoise` to control detail strength (start with 0.2 – 0.5).

**When using Krea 2 with a single node, do you need to connect a Patch node?**
`reference_mode` If it's turned on, you don't need to (internal self-built mechanism of the same type, it will be automatically ignored if connected); if it's turned off (conditioning path), **it must be connected**, otherwise the reference is silently discarded by the core. See the above explanation of the Patch node.
