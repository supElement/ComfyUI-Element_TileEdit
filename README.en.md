# ComfyUI-Element_TileEdit
  <sub> Original Name: ComfyUI-Element_TileUpscale </sub>

A ComfyUI extension designed for image editing models, providing block-by-block refinement, editing, and upscaling (single image only), with powerful block control and local refinement capabilities.
Supported models: Qwen-Image 2.1 / Edit 2509 / 2511, FLUX.3 / FLUX.2 klein, Krea2 + identity_edit lora, Moss + Moss-Image-Edit lora, MiniMax-H3-Image.

✨ Block Upscaling: Say goodbye to cross-block tearing in traditional img2img.
Use block references to ensure consistency across blocks. You can confidently push Denoise redraw strength up to 0.7–1.0 while perfectly maintaining the identity, structure, and texture details of the original image. Supports custom reference strength per sampling step, precisely balancing "repair strength" and "consistency," something traditional img2img block upscaling cannot achieve.

✨ Block Control and Local Refinement: Replace masks with spatial blocks.
Manual split mode (by Manual) provides true "semantic isolation at the block level" and pixel-level control. For example: You can precisely select the layer containing the "white shirt" and only input "change to blue shirt" in the corresponding Layer's Prompt. The background, hair, table, etc., not selected will automatically fall into the Gap fill (filling) area, not receiving the instruction (or only receiving basic global quality enhancement instructions), thus perfectly preserving the original state.
> Operation method: CTRL + left-click drag to add blocks.
> Independent Upscaling: Each manually split layer can have its own upscaling size, allowing core editing areas to achieve higher resolution and detail expression.
> ⚠️ Editing with Krea2 model requires pairing with [krea2_identity_edit](https://huggingface.co/conradlocke/krea2-identity-edit/tree/main) lora.
> ⚠️ Editing with Moss model requires pairing with [Moss-Image-Edit](https://huggingface.co/chinoll/Moss-Image-Edit/tree/main) lora.

## Why It's Needed
Editing models are very picky about whole-image input:

> Image too large —— Most models start to degrade when the image exceeds 2K, some even above 1K, or even ignore instructions;
> 
> Target too small —— When the area to be refined is too small compared to the whole image, direct editing is often ineffective or yields poor results;
> 
> Too many instructions —— A single image cannot hold too many instructions, multiple instructions interfere with each other, and each other is forgotten.

After blocking: Each block returns to the model's comfortable resolution; small targets occupy their own block and can also have their own upscaling multiplier; each instruction is only written into its own layer prompt, and unselected areas are automatically assigned to Gap fill, preserving the original state—in spatial isolation instead of stacking instructions.

> Upscaling: The dead end of img2img
> 
> Traditional block upscaling (TTP, Ultimate SD Upscale, etc.) follows the img2img path, where "redraw strength" and "feature retention" share the same denoise channel: too low results in a plastic-like blur, too high causes identity drift, and denoise values are locked between 0.1–0.5.

This extension injects the original image as an independent reference signal into the model—not participating in noise addition, not decaying with denoise, and supporting scheduling reference strength per sampling step. Denoise only handles redraw strength, which can be pushed to 0.7–1.0: details are generated by the model, identity and structure are anchored by each step's visible reference, achieving both clarity and consistency at the same time; seams are blended with feathering weights + optional per-block color matching to eliminate seams.  
Neighbor context (only for integrated nodes): Already generated adjacent blocks are fed back to the next block as input context with full intensity, making the model treat it as "content to be continued," rather than relying on blurred overlapping areas to hide seams. (For reference-anchored models, neighbor context mainly softens the microscopic texture of the seam band when denoise < 1; consistency of structure and identity is handled by the shared original image reference, which is why redo_first_tile is almost ineffective for editing models.)

### Known Limitations and Disadvantages

#### 1. Relies on specific model capabilities, not friendly to non-image editing models

> The entire value of the node is built on the premise that the **model has reference potential space reference capabilities**. Using models like SDXL, ordinary Flux t2i, Qwen-Image-2512 without reference capabilities will degrade into a normal tiled img2img—**at this point, it is no better than tools like TTP**.

#### 2. Model recognition depends on reverse engineering, may have cross-version stability issues in comfyUI

> Model recognition relies on **class name substring matching** (`"flux" in type(dm).__name__.lower()`), **tokenizer signature reflection** (`inspect.signature`), and `vars()` traversal. None of these are stable APIs.
> 
> Krea2's in-context path involves **manually reconstructing forward propagation** by directly calling `dm.blocks`, `dm.pe_embedder`, `img_slice`, etc., internal structures; the Patch node also depends on core's `extra_conds` object-patch and DIFFUSION_MODEL wrapper mechanisms. Once upstream model implementations change (renaming, changing signatures, changing internal layouts), the node may **silently fail or crash directly**.

#### 3. Higher performance and memory overhead (within acceptable limits)

> Each tile must **independently encode the reference latent**; when grounding is enabled, each tile must also **go through the text encoder's vision encoding** again. The more blocks, the linearly increasing this overhead.
> 
> Krea2's in-context path requires running the full DiT forward pass, with token sequences being `text + source + target` three-segment concatenated, attention costs higher than the original long sequence.
> 
> As the number of tokens in a tile increases, attention costs grow **quadratically**, so automatic tile sizes are limited to 1024–1536. The training resolution limit for identity-edit LoRA is about 2MP, and tiles should not exceed 2MP (1536²≈2.36MP is already over the limit, 1408²≈1.98MP is close to the limit).

#### 4. Does not guarantee correctness for unadapted models

Details are fully generated by the model, while identity / structure remains consistent |
| **Qwen-Image Edit 2511** | **1.0** | 384×384 vision bucket + reference latent dual channel | ★★★★ | Same as 2509, recommend using 1.0 directly, lacks details |
| **Qwen-Image Edit 2509** | **1.0** | 384×384 vision bucket + reference latent dual channel | ★★★★ | Same source as 2511, reference channel mature, can be pushed to maximum, lacks details |
| **FLUX.2 klein base** | **0.7 – 1.0** | Only reference-latent channel (text encoder is pure text, no vision grounding) | ★★★★ | Lacks vision channel, faces look oily, color bias, can use [Smart merge images node](https://github.com/supElement/ComfyUI_Element_easy) for color or deformation correction, can be improved to ★★★★★☆ when combined with anti-shift LoRA |
| **Krea2 + krea2_identity_edit** | **0.7 – 0.8** | Manually reconstruct `[text｜source(frame=1)｜target(frame=0)]` in-context forward | ★★★☆ | Best color consistency under high denoising, but sometimes dirty spots appear, 0.7–0.8 is the best balance between clarity and stability |
| **MiniMax-H3-Image** | **0.8 - 1.0** | conditioning's `minimax_refs` reference channel (re-injected verbatim per step) + `Picture 1:` vision | ★★★☆ | Reference injected as an independent sequence segment, vision short side 1024, VAE reference short side 1024–2048. Recommend block resolution around 4MP, low resolution can't lock composition, structure will drift. |
| **FLUX.3 klein turbo** | **0.7 – 0.8** | text encoder only text effective, no vision grounding | ★★★ | Lacks details, prone to deformation (may be due to comfyUI implementation issues), advantage is not easy to get dirty |
| **FLUX.2 klein turbo** | **0.7 – 0.8** | Only reference-latent channel (text encoder is pure text, no vision grounding) | ★★★ | Lacks vision channel, reference signal one level weaker, very easy to get dirty, color bias, can use [Smart merge images node](https://github.com/supElement/ComfyUI_Element_easy) for color or deformation correction, can be improved to ★★★☆ when combined with anti-shift LoRA |
| **MOSS-Image + Moss-Image-Edit** | **0.7 – 1** | Native `reference_latents` channel, uses `index_timestep_zero_text_start` layout; ComfyUI automatic pre-computation `ref_kv` acceleration | ★★☆ | New comfyUI natively supports Edit LoRA. Leverages 1:1 size reference injection. Weak in visual semantic completion, global context understanding, and prior knowledge, resulting in insufficient details and blurriness. Due to involving first-step K/V pre-computation, the first step is slightly longer. Recommend pairing with the latest ComfyUI version (#17296). |
| **Qwen-Image-2512/SDXL series** | **0.2 – 0.5** | None | ★ | Non-editing models lack consistency anchoring, even with methods like ipadapter, the effect is still limited |

> CFG values should be set according to the model being used.
> 
> Editing model denoise range 0.6–1.0; non-editing model denoise value should not exceed 0.5.
> 
> Model combination strategy: It is recommended to use non-distilled models like base or raw, combined with turbo LoRA (weight about 0.8, adjust according to specific model). This can balance high-quality detail restoration of the base model with generation speed of the distilled model, and effectively avoid high-frequency artifacts (dirty spots) when directly using pure turbo models.
> 
> Reference strength curve (reference_strength): It is recommended to use an "early high, late low" relaxation curve at the end. For example, when the total steps are 4, you can set 1.0, 1.0, 0.9, 0.8. Since turbo models have very few steps, the strength of each step greatly affects the result. It is recommended that the reference strength throughout should not be below 0.7 (otherwise it is easy to cause image drift); if feature drift occurs in actual use, the curve can be directly flattened to all 1.0.
> 
> Krea2 model tuning (when using Krea2 identity-edit mode in integrated nodes, `reference_mode` needs to be enabled): It is recommended to leave the negative_prompt completely empty. This is because krea2's identity-edit uses unconditional distribution of "the same image + empty text" during training, leaving it empty can perfectly align with the training distribution; and at cfg=1.0, the node can also save the encoding time of negative prompt words.

#### The number of tests is limited, there are subjective and biased factors, and parameters still need to be adjusted according to different situations. Of course, you can also improve the results by using enhanced LoRA or fine-tuned models, but this is not within the scope of the test.

## Global Prompt (Non by manual mode)

> In non-manual block mode (e.g., integrated nodes, by count, by size), this node will apply the same global prompt to every text encoding of the block. Since each block only covers a small local area of the original image, the specific content of this area is completely determined by the reference image (pixel features), while the prompt only guides the model "how to process" this content.
> 
> Therefore, the global prompt must follow the core principle of "generally applicable to all blocks":

### ✅ Should Write
1. Operational instructions —— Tell the model the core task of this sampling (applies to each block):
  - sharpen and refine details, preserve identity and structure, clean upscale  
  - (Sharpen and refine details, preserve identity and structure, cleanly upscale)

2. Global style / lighting / color tone —— The atmosphere common to the entire image (also applies to each block):
  - cool blue ambient lighting, warm orange rim light, cinematic tone, photorealistic  
  - (Cool blue ambient light, warm orange rim light, cinematic tone, photorealistic)

### ❌ Should Not Write
  - Specific object, character, or scene nouns (e.g., woman at a computer, glasses, monitor, coffee cup).
  - Unless you can be sure that the prompt describes object elements that apply to every block in the image.

### 💡 Recommended Template
  - sharpen and refine, preserve identity and structure, {global tone/lighting/style}, {quality terms}

## Node Overview

| Node | Function |
|---|---|
| **Element Tiled Upscale** | Integrated node: Upscale → Split → Per-tile reference redraw → Frequency separation fusion, one-click output |
| **Element Tile Split** | Pure geometric splitting + Image source input, no model dependency. The backend will fully recalculate geometry during execution, while the frontend UI only does preview. |
| **Element Tile Encode** | Encodes each tile image / prompt into per-tile LATENT + CONDITIONING, samplingAssign to ComfyUI Native KSampler |
| **Element Tile Merge** | Merges the list of images after per-tile decoding using the same low-frequency/high-frequency separation + feathering weight, with optional per-tile color matching |
| **Element Krea2 In-Context Patch** | Model patch: Allows Krea2 to consume reference latentHanging on conditioning Up with identity-edit in-context layout |
| **Element Strength Schedule** | Model patch: Attaches the progressive reference_strength schedule to the model, for use in ElementTileSplit + native KSampler workflows. KSampler's model input must connect to the output of this node. The integrated node includes the same scheduler and ignores upstream attachments; single-node workflows use its built-in parameters directly. The i-th value affects the i-th sampling step (starting from 0); if fewer than steps, repeat the last value; if more, truncate; single value = constant. 1.0 = full reference; 0 = no reference for that step; pure 0/1 list uses singleDouble computing power, values ≠1 with decimals use double forward. Lower parameter settings increase drift; to ensure consistency, set higher values for the first few steps. It's recommended to set the first few steps to 1 and gradually lower them for later steps based on the model used, which is more beneficial for flaw repair. Invalid for non-image editing models like sdxl, Qwen image 2512, etc. |

## Common Issues

**How to use?**  
- Workflows are provided in the workflow folder.  
- The ElementTiledUpscale_Qwenimage2.1_Split_UseGenerateText.json workflow demonstrates how to use ComfyUI's built-in Generate Text node to automatically expand and refine short prompts. However, since it requires running a local LLM, it will significantly increase generation time.

**How to split manually?**

- Use the by manual mode in the Element Tile Split node. Hold down CTRL + left mouse button on the canvas and drag to add splits; you can add multiple splits consecutively.  
- Each added split will add a corresponding layer in the right panel, and each layer can have its own prompt set in the layer prompts below.  
- Drag layers with the mouse to adjust their order. The merge node will merge the top layer last, so ensure the top layer is fully visible when multiple manual splits overlap.  
- Independent corner rounding: After selecting a layer, drag the cyan dots on the four corners to independently adjust the corner radius. The background padding will automatically fit the outer contour of the rounded corners.  
- You can delete unwanted splits (layers) by pressing delete, or click the delete button on the corresponding layer to remove them.

**Does the input image need to be divisible by div?**  
- No. The split canvas only aligns `div` internally, with any extra edges absorbed by padding blocks moving inward. The crop still comes entirely from real pixels; the merge output size matches the original image size exactly.  
- A single block will be padded with edge pixels to the canvas size for generation, then cropped back after merging; `div` always only constrains the resolution of each block generated, not the output size.

**Insufficient VRAM?**  
- Reduce tile_size (more splits, smaller blocks). For Edit 2509/2511, you can additionally lower grounding_px; Qwen 2.1's grounding_px is not involved in calculations, so only tile_size can be reduced.

**MiniMax-H3-Image position shift after upscaling?**  
- MiniMax-H3-Image is not suitable for low-resolution split images. Solution: Increase the resolution of each block to around 4MP.

**Can SDXL and other normal models be used?**  
- Yes. The node automatically degrades to a normal split img2img, with reference latent ignored by the model, using denoise to control detail strength (start with 0.2 – 0.5).

**Do I need to connect the Patch node when using Krea 2 with a single node?**  
- `reference_mode` enabled = no (internal self-built mechanism, connections are automatically ignored); disabled (conditioning path) **must** be connected, otherwise the reference is silently discarded by the core. See the Patch node explanation above.

**How to reduce color bias and distortion during redraw/editing**  
- Use the split node, enable the enable mask option in the split node (no need to draw a mask manually). The model will reference the locked area (mask = 0) and redraw the unlocked area (mask = 1), giving the model more reference to the original area. Increase overlap values, adjust lock and feather parameters. To understand the relationship between these parameters, see the Detailed Parameter Explanation.
