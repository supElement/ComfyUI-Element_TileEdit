# ComfyUI-Element_TileEdit
  <sub> Original Name: ComfyUI-Element_TileUpscale </sub>

A ComfyUI extension designed for image editing models, providing powerful tile control and local refinement capabilities for tiling enhancement/editing/magnification (single image only).

Supported models: Qwen-Image 2.1 / Edit 2509 / 2511, FLUX.3 / FLUX.2 klein, Krea2 + identity_edit lora, Moss + Moss-Image-Edit lora.

✨ Tile-based magnification: Say goodbye to cross-tile tearing in traditional img2img.
Use tile references to ensure cross-tile consistency. You can confidently push Denoise redraw strength up to 0.7–1.0 while perfectly preserving the identity, structure, and texture details of the original image. Supports custom reference strength per sampling step to precisely balance "repair strength" and "consistency," something traditional img2img tile magnification cannot achieve.

✨ Tile control and local refinement: Replace masks with spatial tiling.
The manual split mode (by Manual) provides true "tile-level semantic isolation" and pixel-level control. For example: You can precisely select the layer containing the "white shirt" and input only "change to blue shirt" in the corresponding Layer's Prompt. The background, hair, table, etc., not selected will automatically fall into the Gap fill (filling) area and will not receive the instruction (or only receive basic global quality enhancement instructions), thus perfectly maintaining their original state.
> Operation method: CTRL + left-click drag to add tiles.
> Independent magnification: Each manually split layer can have its own magnification size set, allowing the core editing area to achieve higher resolution and detail expression.
> ⚠️ Editing with Krea2 model requires pairing with [krea2_identity_edit](https://huggingface.co/conradlocke/krea2-identity-edit/tree/main) lora.
> ⚠️ Editing with Moss model requires pairing with [Moss-Image-Edit](https://huggingface.co/chinoll/Moss-Image-Edit/tree/main) lora.

## Why it's needed
Editing models are very picky about full-image input:

> Image too large —— Most models start to degrade when the image exceeds 2K, some even above 1K, or even ignore instructions;
> 
> Target too small —— When the area to be refined is too small compared to the full image, direct editing is often ineffective or yields poor results;
> 
> Too many instructions —— A single image cannot hold too many instructions, multiple instructions interfere with each other, and are forgotten.

After tiling: Each tile returns to the model's comfortable resolution; small targets occupy their own tile and can also have their own magnification set; each instruction is written into its own layer's prompt, and unselected areas are automatically assigned to Gap fill, maintaining their original state—using spatial isolation instead of instruction stacking.

> Magnification: The dead end of img2img
> 
> Traditional tile magnification (TTP, Ultimate SD Upscale, etc.) follows the img2img path, where "redraw strength" and "feature preservation" share the same denoise channel: too low results in a plastic-like blur, too high causes identity drift, and denoise values are locked between 0.1–0.5.

This extension injects the original image as an independent reference signal into the model—not participating in noise addition, not attenuating with denoise—and supports scheduling reference strength per sampling step. Denoise only handles redraw strength, which can be pushed to 0.7–1.0: details are generated by the model, identity and structure are anchored by each step's visible reference, achieving both clarity and consistency simultaneously; seams are blended using feathering weights + optional per-tile color matching to eliminate seams.  
Neighbor context (only for integrated nodes): Already generated adjacent tiles feed back to the next tile as input context at full strength, making the model treat them as "content to continue," rather than relying on blurred overlaps to hide seams. (For reference-anchored models, neighbor context mainly softens the micro-texture of the seam band when denoise < 1; consistency of structure and identity is handled by the shared original image reference, which is why redo_first_tile is almost ineffective for editing models.)

### Known limitations and drawbacks

#### 1. Relies on specific model capabilities and is not friendly to non-image editing models

> The entire value of the node is built upon the assumption that the **model has reference potential space reference capabilities**. When using models like SDXL, ordinary Flux t2i, Qwen-Image-2512 without reference capabilities, it degrades into a normal tiled img2img—**at this point, it is no better than tools like TTP**.

#### 2. Model recognition depends on reverse engineering, which may have cross-version stability issues in ComfyUI

> Model recognition relies on **class name substring matching** (`"flux" in type(dm).__name__.lower()`), **tokenizer signature reflection** (`inspect.signature`), and `vars()` traversal. None of these are stable APIs.
> 
> Krea2's in-context path involves **manually reconstructing the forward propagation** by directly calling `dm.blocks`, `dm.pe_embedder`, `img_slice`, etc., internal structures; the Patch node also depends on core's `extra_conds` object-patch and DIFFUSION_MODEL wrapper mechanisms. Once the upstream model implementation changes (renaming, changing signature, changing internal layout), the node may **silently fail or crash directly**.

#### 3. Higher performance and memory overhead (within acceptable limits)

> Each tile must **independently encode the reference latent**; when grounding is enabled, each tile must also **go through the text encoder's vision encoding** again. The more tiles, the linearly increasing this overhead.
> 
> Krea2's in-context path requires running the full DiT forward pass, with token sequences being `text + source + target` three-segment concatenated, attention costs higher than the original long sequence.
> 
> As the number of tokens in a tile increases, attention costs grow **quadratically**, so automatic tile sizes are limited to 1024–1536. The training resolution limit for identity-edit LoRA is about 2MP, and tiles should not exceed 2MP (1536²≈2.36MP is already over the limit, 1408²≈1.98MP is close to the limit).

#### 4. Does not guarantee correctness for unadapted models

## Recommended Denoising Values and Combinations

| Model | Recommended Denoising Value | Reference Injection Method | Consistency | Description |
|---|---|---|---|---|
| **Qwen-Image 2.1** | **1.0** | Refer to latent precise insertion at vision token positions (image_slots), tile remains original size without resize | ★★★★★ | Reference signal is most native, can be pushed to the maximum in most cases. Details are completely generated by the model, while identity / structure remains consistent |
| **Qwen-Image Edit 2511** | **1.0** | 384×384 vision bucket + reference latent dual channel | ★★★★ | Same as 2509, recommend using 1.0 directly, lacks details |
| **Qwen-Image Edit 2509** | **1.0** | 384×384 vision bucket + reference latent dual channel | ★★★★ | Same source as 2511, reference channel is mature, can be pushed to the maximum, lacks details |
| **FLUX.2 klein base** | **0.7 – 1.0** | Only reference-latent channel (text encoder is pure text, no vision grounding) | ★★★★ | Lacks vision channel, some oily faces, color bias, can use [Smart merge images node](https://github.com/supElement/ComfyUI_Element_easy) for color or deformation correction, can be improved to ★★★★★☆ when combined with anti-shift LoRA |
| **Krea2 + krea2_identity_edit** | **0.7 – 0.8** | Manually reconstruct `[text｜source(frame=1)｜target(frame=0)]` in-context forward | ★★★☆ | Best color consistency under high denoising, but sometimes dirty spots may appear, 0.7–0.8 is the best balance between clarity and stability |
| **FLUX.3 klein turbo** | **0.7 – 0.8** | text encoder only text is effective, no vision grounding | ★★★ | Lacks details, prone to deformation (may also be a problem of comfyUI implementation), advantage is not easy to get dirty |
| **FLUX.2 klein turbo** | **0.7 – 0.8** | Only reference-latent channel (text encoder is pure text, no vision grounding) | ★★★ | Lacks vision channel, reference signal is one level weaker, very easy to get dirty and color biased, can use [Smart merge images node](https://github.com/supElement/ComfyUI_Element_easy) for color or deformation correction, can be improved to ★★★☆ when combined with anti-shift LoRA |
| **MOSS-Image + Moss-Image-Edit** | **0.7 – 1** | Native `reference_latents` channel, uses `index_timestep_zero_text_start` layout; ComfyUI automatic pre-computation `ref_kv` acceleration | ★★☆ | New comfyUI natively supports Edit LoRA. With 1:1 size reference injection. Weaker in visual semantic completion, global context understanding, and prior knowledge, resulting in insufficient details and blurriness. Due to involving first-step K/V pre-computation, the first step is slightly longer in time. Recommend using the latest version of ComfyUI (#17296). |
| **Qwen-Image-2512/SDXL series** | **0.2 – 0.5** | None | ★ | Non-editing models lack consistency anchoring, even with methods like ipadapter, the effect is still limited |

> CFG values should be set according to the model being used.
> 
> Editing model denoise range 0.6–1.0; non-editing model denoise value should not exceed 0.5.
> 
> Model combination strategy: It is recommended to use base or raw non-distilled models, combined with turbo LoRA (weight about 0.8, adjust according to specific model). This can balance the high-quality detail restoration of the base model with the generation speed of the distilled model, and can effectively avoid high-frequency artifacts (dirty spots) when directly using pure turbo models, which are prone to amplification.
> 
> Reference strength curve (reference_strength): It is recommended to use an "early high, late low" tail relaxation curve. For example, when the total steps are 4, you can fill in 1.0, 1.0, 0.9, 0.8. Since turbo models have very few steps, the strength of each step greatly affects the result, it is recommended that the reference strength throughout should not be less than 0.7 (otherwise it is easy to cause image drift); if feature drift occurs in actual use, the curve can be directly flattened to all 1.0.
> 
> Krea2 model tuning (when using Krea2 identity-edit mode in integrated nodes, `reference_mode` needs to be turned on): It is recommended to leave the negative_prompt completely empty. This is because krea2's identity-edit uses an unconditional distribution of "the same image + empty text" during training, leaving it empty can perfectly align with the training distribution; and when cfg=1.0, the node can also save the encoding time of negative prompt words.

#### The number of tests is limited, there are subjective and one-sided factors, and parameters still need to be adjusted according to different situations. Of course, you can also improve the results by using enhanced LoRA or fine-tuned models, but this is not within the scope of the test.

## Global Prompt (Non by manual mode)

> In non-manual block mode (such as integrated nodes, by count, by size), this node will apply the same global prompt to every text encoding of the block. Since each block only covers a small local area of the original image, the specific content of this area is completely determined by the reference image (pixel features), while the prompt is only responsible for guiding the model "how to process" this content.
> 
> Therefore, the global prompt must follow the core principle of "generally applicable to all blocks":

### ✅ Should Write
1. Operation instructions — Tell the model the core task of this sampling (applies to each block):
  - sharpen and refine details, preserve identity and structure, clean upscale  
  - (Sharpen and refine details, preserve identity and structure, cleanly upscale)

2. Global style / lighting / tone — The atmosphere of the entire image (also applies to each block):
  - cool blue ambient lighting, warm orange rim light, cinematic tone, photorealistic  
  - (Cool blue ambient light, warm orange rim light, cinematic tone, photorealistic)

### ❌ Should Not Write
  - Specific object, character, or scene nouns (e.g., woman at a computer, glasses, monitor, coffee cup).
  - Unless you can be sure that the prompt describes object elements that apply to every block in the image.

### 💡 Recommended Template
  - sharpen and refine, preserve identity and structure, {global tone/lighting/style}, {image quality terms}

## Node Overview

| Node | Function |
|---|---|
| **Element Tiled Upscale** | Integrated node: Upscale → Split → Per-tile reference redraw → Frequency separation fusion, one-click output |
| **Element Tile Split** | Pure geometric splitting + image source input, no model dependency. Geometric calculations are fully recalculated during backend execution, UI only does previewing. |
| **Element Tile Encode** | Encodes each image / prompt into per-tile LATENT + CONDITIONING, sampling delegated to ComfyUI native KSampler |
| **Element Tile Merge** | Merges the list of images after per-tile decoding using the same low-frequency/high-frequency separation + feathering weight, optional per-tile color matching |
| **Element Krea2 In-Context Patch** | Model patch: Allows Krea2 to consume reference latent attached to conditioning with an identity-edit in-context layout |
| **Element Strength Schedule** | Model patch: Attaches the progressive reference_strength scheduling to the model, for use by ElementTileSplit + native KSampler workflow, KSampler's model input must connect to the output of this node. The integrated node has the same scheduling built-in and will ignore upstream attachments, single-node workflow directly uses its built-in parameters. The i-th value affects the i-th sampling step (starting from 0); if fewer than steps, repeat the last value; if more, truncate; single value = constant. 1.0 = full reference; 0 = no reference for this step; pure 0/1 list uses single multiplier, decimal values ≠ 1 use double forward. Lower parameter settings increase drift, to ensure consistency, set higher values for the first few steps, recommend setting 1 for the first few steps and gradually lowering for the latter steps based on the model used, this setting is more beneficial for flaw repair. Invalid for non-image editing models, such as sdxl, Qwen image 2512, etc. |

## Common Issues

**How to use?**  
- Workflows are already provided in the workflow folder.  

**How to split manually?**

- Must use the by manual mode in the Element Tile Split node. Hold down CTRL + left mouse button on the canvas and drag to add splits, can be added consecutively.
- Each added split will add a corresponding layer in the right panel, each layer can set a prompt separately in the layer prompts below.
- Drag layers with the mouse to adjust the layer order, the merge node will merge the top layer last, so ensure the top layer is fully visible when multiple manual splits overlap.
- Independent corner rounding: After selecting a layer, drag the cyan dots on the four corners to independently adjust the corner radius. The background padding will automatically fit the outer contour of the rounded corners.
- Unneeded splits can be deleted by pressing delete (layer), or by clicking the delete button on the corresponding layer.

**Out of VRAM?**  
- Reduce tile_size (more splits, smaller per-split size). Edit 2509/2511 can additionally lower grounding_px; Qwen 2.1's grounding_px does not participate in calculations, only tile_size can be reduced.

**Can SDXL and other normal models be used?**  
- Yes. The node automatically degrades to normal img2img splits, reference latent is ignored by the model, and detail strength is controlled by denoise (start with 0.2 – 0.5).

**Do I need to connect a Patch node when using Krea 2 with a single node?**  
- `reference_mode` is on, no need (internal self-built mechanism, connections will be automatically ignored); off (conditioning path) **must** be connected, otherwise the reference is silently discarded by the core. See the Patch node explanation above.
