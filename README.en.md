# ComfyUI-Element_TileEdit
  <sub> Original Name: ComfyUI-Element_TileUpscale </sub>

A ComfyUI extension designed for image editing models, providing powerful tile control and local refinement capabilities for upscaling (single image only).
Supported models: Qwen-Image 2.1 / Edit 2509 / 2511, FLUX.3 / FLUX.2 klein, Krea2 + identity_edit lora, Moss + Moss-Image-Edit lora, MiniMax-H3-Image, MiniMax-H3-Video (only split node workflow).

✨ Tile-based Upscaling: Say goodbye to cross-tile tearing in traditional img2img.
Use tile references to ensure cross-tile consistency. You can confidently push Denoise redraw strength up to 0.7–1.0 while perfectly maintaining the identity, structure, and texture details of the original image. Supports custom reference strength per sampling step to precisely balance "repair strength" and "consistency," something traditional img2img tile upscaling cannot achieve.

✨ Tile Control and Local Refinement: Replace masks with spatial tiles.
The manual split mode (by Manual) provides true "tile-level semantic isolation" and pixel-level control. For example: you can precisely select the layer containing the "white shirt" and only input "change to blue shirt" in the corresponding Layer's Prompt. The background, hair, table, etc., not selected will automatically fall into the Gap fill (filling) area and will not receive the instruction (or only receive basic global quality enhancement instructions), thus perfectly preserving their original state.
> Operation method: CTRL + left-click drag to add tiles.
> Independent Upscaling: Each manually split layer can have its own upscaling size, allowing the core editing area to achieve higher resolution and detail expression.
> ⚠️ Editing with Krea2 model requires pairing with [krea2_identity_edit](https://huggingface.co/conradlocke/krea2-identity-edit/tree/main) lora.
> ⚠️ Editing with Moss model requires pairing with [Moss-Image-Edit](https://huggingface.co/chinoll/Moss-Image-Edit/tree/main) lora.

## Why It's Needed
Editing models are very picky about whole-image input:

> Image too large —— Most models start to degrade when the image exceeds 2K, some even above 1K, or even ignore instructions;
> 
> Target too small —— When the area to be refined is too small compared to the whole image, direct editing is often ineffective or yields poor results;
> 
> Too many instructions —— A single image cannot hold too many instructions, multiple instructions interfere with each other, and each other is forgotten.

After splitting: Each tile returns to the model's comfortable resolution; small targets occupy their own tile and can also set their own magnification factor; each instruction is only written into its own layer prompt, and the unselected areas are automatically assigned to Gap fill, preserving their original state—in place of instruction stacking with spatial isolation.

> Upscaling: The dead end of img2img
> 
> Traditional tile upscaling (TTP, Ultimate SD Upscale, etc.) follows the img2img path, where "redraw strength" and "feature retention" share the same denoise channel: too low results in a plastic-like blur, too high causes identity drift, and denoise values are locked between 0.1–0.5.

This extension injects the original image as an independent reference signal into the model—not participating in noise addition, not decaying with denoise—and supports scheduling reference strength per sampling step. Denoise only handles redraw strength, which can be pushed to 0.7–1.0: details are generated by the model, identity and structure are anchored by each step's visible reference, achieving both clarity and consistency simultaneously; seams are blended with feathering weights + optional per-tile color matching to eliminate seams.  
Neighbor context (only for integrated nodes): Already generated adjacent tiles will feed back as input context to the next tile at full intensity, making the model treat it as "content to be continued," rather than relying on overlapping areas to obscure seams with blurred mixing. (For reference-anchored models, neighbor context mainly softens the microscopic texture of the seam band when denoise < 1; consistency of structure and identity is handled by the shared original image reference, which is why redo_first_tile is almost ineffective for editing models.)

### Known Limitations and Disadvantages

#### 1. Relies on specific model capabilities and is not friendly to non-image editing models

> The entire value of the node is built upon the premise that **the model has reference potential space reference capabilities**. Using models like SDXL, ordinary Flux t2i, Qwen-Image-2512 without reference capabilities will degrade into a normal tiled img2img—in this case, it is **no better than tools like TTP**.

#### 2. Higher performance and memory overhead (within acceptable limits)

> Each tile must **independently encode the reference latent**; when grounding is enabled, each tile must also **go through the text encoder's vision encoding** again. The more tiles, the linearly increasing this overhead.
> 
> Krea2's in-context path requires running the full DiT forward, with token sequences being `text + source + target` three segments concatenated, attention costs higher than the original long.
> 
> As the number of tokens in a tile increases, attention costs grow **quadratically**, so automatic tile sizes are limited to 1024–1536. The training resolution limit of identity-edit LoRA is about 2MP, and tiles should not exceed 2MP (1536²≈2.36MP is already over the limit, 1408²≈1.98MP is close to the limit).

#### 3. Does not guarantee correctness for unadapted models

> The adapted families are: Krea 2 (identity-edit), MiniMax-H3-Image, MiniMax-H3-Video (split node), p-h3-image, Qwen Image 2.1, Qwen Edit 2509/2511, FLUX.2 Klein, FLUX.3 Klein, MOSS-Image, and general models supporting reference_latents. Other models (Qwen-Image-2512, SDXL series, ordinary Flux t2i, etc.) will degrade into normal tiled img2img.
> Adaptable models only need to select `model_type` (auto = auto-identify) once in **Element Strength Schedule**, Encode will read the same selection as MODEL; without Schedule, Encode auto-identifies. Krea2's identity-edit requires turning on reference_mode, and its in-context forward needs to adapt parts that synchronize with the upstream internal layout.

Leverages 1:1 size reference injection. Weak in visual semantic completion, global context understanding, and prior knowledge, resulting in insufficient details and blur. Due to first-step K/V pre-computation, the first step is slightly longer. Recommend pairing with the latest ComfyUI version (#17296). |
| **Qwen-Image-2512/SDXL series** | **0.2 – 0.5** | None | ★ | Non-editing models lack consistency anchoring, even with methods like ipadapter, the effect is still limited |

> CFG values should be set according to the model being used.
> 
> Editing model denoise range 0.6–1.0; non-editing model denoise value should not exceed 0.5.
> 
> Model combination strategy: It is recommended to use non-distilled models like base or raw, paired with turbo LoRA (weight about 0.8, adjust according to specific model). This balances high-quality detail restoration of the base model with generation speed of the distilled model, and effectively avoids high-frequency artifacts (dirty spots) that can be amplified when using pure turbo models directly.
> 
> Reference strength curve (reference_strength): It is recommended to use an "early high, late low" relaxation curve at the end. For example, when the total steps are 4, you can set 1.0, 1.0, 0.9, 0.8. Since turbo models have very few steps, the strength of each step greatly affects the result. It is recommended that the reference strength throughout should not be below 0.7 (otherwise it is prone to image drift); if feature drift occurs in actual use, the curve can be directly flattened to all 1.0.
> 
> Krea2 model tuning (when using Krea2 identity-edit mode in integrated nodes, `reference_mode` needs to be turned on): It is recommended to leave the negative_prompt completely empty. This is because krea2's identity-edit unconditional distribution during training is "the same image + empty text", leaving it empty aligns perfectly with the training distribution; and when cfg=1.0, the node can also save the encoding time of negative prompt words.

#### The above test quantity is limited, there are biases and subjective factors, and parameters still need to be adjusted according to different situations. Of course, you can also improve the results by using enhanced LoRA or fine-tuned models, but this is not within the scope of the test.

## Global Prompt (Non by manual mode)

> In non-manual block mode (e.g., integrated nodes, by count, by size), this node will apply the same global prompt to every text encoding of the block. Since each block only covers a small local area of the original image, the specific content of this area is completely determined by the reference image (pixel features), while the prompt only guides the model "how to process" this content.
> 
> Therefore, the global prompt must follow the core principle of "generally applicable to all blocks":

### ✅ Should Write
1. Operational instructions —— Tell the model the core task of this sampling (applies to each block):
  - sharpen and refine details, preserve identity and structure, clean upscale  
  - (Sharpen and refine details, preserve identity and structure, cleanly upscale)

2. Global style / lighting / color tone —— The atmosphere common to the entire image (also applies to each block):
  - cool blue ambient lighting, warm orange rim light, cinematic tone, photorealistic  
  - (Cool blue ambient light, warm orange rim light, cinematic tone, photorealistic)

### ❌ Should Not Write
  - Specific object, character, or scene nouns (e.g., woman at a computer, glasses, monitor, coffee cup).
  - Unless you can be sure that the prompt describes object elements that apply to every block in the image.

### 💡 Recommended Template
  - sharpen and refine, preserve identity and structure, {global tone/lighting/style}, {quality terms}

## Node Overview

| Node | Function |
|---|---|
| **Element Tiled Upscale** | Integrated node: Upscale → Split → Per-tile reference redraw → Frequency separation fusion, one-click output |
| **Element Tile Split** | Pure geometric splitting + Image source input, no model dependency. The backend recalculates geometry in full during execution, while the frontend UI only serves as a preview. Outputs a single `tile_info` port. |
| **Element Tile Info** | Expands Split's `tile_info` into `split_images / tile_masks / prompt / negative_prompt / grid / original_image` six ports, no parameters |
| **Element Tile Encode** | Encodes each image / prompt into per-tile LATENT + CONDITIONING, sampling delegated to ComfyUI's native KSampler |
| **Element Tile Merge** | Merges the list of per-tile decoded IMAGES using the same low-frequency/high-frequency separation + feathering weight, with optional per-tile color matching |
| **Element Krea2 In-Context Patch** | Model patch: Allows Krea2 to consume reference LATENT on conditioning in an identity-edit in-context layout |
| **Element Strength Schedule** | Model patch: Attaches a progressive reference_strength schedule to the model, for use in ElementTileSplit + native KSampler workflows. KSampler's model input must connect to this node's output. The integrated node includes the same schedule and ignores upstream attachments, while the single-node workflow directly uses its built-in parameters. The i-th value affects the i-th sampling step (starting from 0); if fewer than steps, repeats the last value; if more, truncates; a single value = constant. 1.0 = full reference; 0 = no reference for that step; a pure 0/1 list uses single multiplicative power, while values ≠1 for steps with decimals use double forward. Lower parameter settings increase drift; to ensure consistency, set higher values for the first few steps, recommend 1 for the first few steps, then lower for the remaining steps based on the model used, which is more beneficial for flaw repair. Invalid for non-image editing models like sdxl, Qwen image 2512, etc. |

## Common Issues

**How to use?**  
- Workflows are provided in the workflow folder.  
- The ElementTiledUpscale_Qwenimage2.1_Split_UseGenerateText.json workflow demonstrates how to use ComfyUI's built-in Generate Text node to automatically expand and refine short prompts. However, since it requires running a local LLM, it significantly increases generation time.

**How to split manually?**

- Use the Element Tile Split node's by manual mode. Hold down CTRL + left mouse button on the canvas, drag to add splits, and can add multiple consecutively.  
- Each added split will add a corresponding layer in the right panel, and each layer can have its own prompt set in the layer prompt below.  
- Drag layers with the mouse to adjust their order. The merge node will merge the top layer last, so ensure the top layer is fully visible when multiple manual splits overlap.  
- Independent corner rounding: After selecting a layer, drag the cyan dots at the four corners to independently adjust the corner radius. The background padding will automatically fit the outer contour of the rounded corners.  
- Unneeded splits can be deleted by pressing delete (layer), or by clicking the delete button on the corresponding layer.

**Does the input image need to be divisible by div?**  
- No. The split canvas only aligns `div` internally, with excess edges absorbed by padding blocks moving inward, and crop still comes from real pixels; Merge output size matches the original size exactly.  
- A single block will be padded with edge pixels to the canvas size for generation, then cropped back; `div` always constrains the resolution of each block generated, without changing the output size.

**Insufficient VRAM?**  
- Reduce tile_size (more splits, smaller blocks). For Edit 2509/2511, you can additionally lower grounding_px; Qwen 2.1's grounding_px is not calculated, only tile_size can be reduced.

**MiniMax-H3-Image position shift after upscaling?**  
- MiniMax-H3-Image is not suitable for low-resolution split images. Solution: Increase the resolution of each block to around 4MP.

**Can SDXL and other normal models be used?**  
- Yes. The node automatically degrades to a normal split img2img, with reference LATENT ignored by the model, using denoise to control detail strength (start with 0.2 – 0.5).

**Do I need to connect the Patch node when using Krea 2 with a single node?**  
- `reference_mode` enabled = no (internal self-built mechanism, connections are automatically ignored); disabled (conditioning path) **must** be connected, otherwise the reference is silently discarded by the core. See the Patch node explanation above.

**How to reduce color bias and distortion during redraw/editing**  
- Use the split node, enable the split node's enable mask option (no need to draw a mask manually), the model will reference the locked area (mask = 0) and redraw the unlocked area (mask = 1), giving the model more reference to the original area, increase overlap value, adjust lock and feather parameters. To understand the relationship between these parameters, see Detailed Parameter Explanation.
